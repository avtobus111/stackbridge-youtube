# Работа с ИИ и происхождение материалов

Код, тесты, конфигурации и документы проекта создавались с Codex в отдельном чате тестового задания. Рабочий процесс: чтение исходного ТЗ → архитектурные решения и план → тесты с наблюдаемыми исходными отказами → реализация → PostgreSQL/FFmpeg и реальные S3/browser-проверки → отдельное ревью → воспроизводящие тесты и исправления.

Применённые проектные правила находятся в корневом AGENTS.md. Снимки фактически прочитанных/использованных скиллов — в skills/, их состав и хеши — в skills-manifest.json. Глобальный Codex config, credentials, MCP-токены и чужие проекты не копируются. Этот проект не имитирует использование Claude/Cursor или других инструментов.

## Нативные диалоги

Codex сохраняет исходную историю в JSONL. Проверка обнаружила, что оригинальный файл этого чата включает автоматически подставленную память о других проектах и технические идентификаторы аккаунта. Пользователь поручил подготовить **полный оригинал отдельно для его проверки перед включением в сдачу**.

Поэтому файлы не редактируются, не пересказываются и не заменяются сгенерированной «историей», но **пока исключены из исходного ZIP**. Отдельный локальный архив `AI_ORIGINALS_REVIEW_ONLY.zip` содержит исходный JSONL и manifest с SHA-256/временем снимка. Он не предназначен для отправки до проверки пользователем. История предыдущего чата поиска работы не экспортировалась; исходник относится только к workspace этого тестового, хотя внутри него есть автоматически внедрённый контекст.

Это существенное отличие текущего комплекта от требования работодателя «оригинальные диалоги в том же ZIP/репозитории». Перед окончательной сдачей нужно разрешить этот вопрос с пользователем: включить проверенный оригинал в общий ZIP или согласовать допустимый формат с работодателем. Очищенная/пересказанная копия не выдаётся за полный оригинал.

Экспорт выполняет `scripts/export_ai.py`. Он проверяет workspace, исключает платформенные guardian/approval-сессии, читает только явно переданные файлы, сохраняет исходные байты и не пишет оригиналы внутрь дерева сдачи. Снимок заканчивается последней полностью записанной строкой на момент экспорта; дальнейшие действия чата потребуют нового снимка.

## Ревью

Для независимой проверки исходников использован один subagent с чистым контекстом, работающий только на чтение. Он проверил код против исходного ТЗ и плана, не менял файлы и не выполнял разрушительные тесты на общем стенде. Проверка нашла две гонки восстановления; их воспроизвели отдельными тестами и исправили. Сводка — в review.md. Сводка является документацией процесса, а не нативным логом.

Ни репозиторий, ни приложение, ни журналы не публиковались и работодателю не отправлялись.
