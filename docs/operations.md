# Запуск и эксплуатация

## Состав

Compose-проект `stackbridge` содержит `db`, `storage`, однократный `initialize`, `web` и `worker`. Внутренние порты БД, S3, filer и master не опубликованы. Публичная точка входа — web:8000. FastAPI обслуживает UI, API и авторизованную выдачу медиа. Данные сохраняются в отдельных томах `postgres-data` и `object-data`.

`initialize` ждёт готовности PostgreSQL/S3, создаёт закрытый bucket `videos`, под блокировкой PostgreSQL применяет Alembic и запускает seed. Web и worker зависят от успешного завершения initialize. `/healthz` проверяет БД и доступ к bucket. Ошибка инициализации видна в логах; приложение не объявляется готовым.

## Повторный запуск и диагностика

```bash
docker compose ps
docker compose logs --tail 100 initialize web worker
docker compose restart web worker
docker compose up -d --build --wait
```

Повторное `bash start.sh` сохраняет `.env`, пароли, тома и созданные пользователем данные. Seed добавляет отсутствующие демо-записи с детерминированными ID; существующие аккаунты не повышаются в правах и не получают новый пароль.

Остановка с сохранением данных: `docker compose down`. Не используйте `down -v` для рабочего проекта: этот флаг удаляет БД и объекты. Изолированные тесты запускаются с другим Compose-именем и не используют тома приложения.

Миграции выполняются до запуска процессов. Новая ревизия: `alembic revision --autogenerate -m "описание"`, обязательная проверка созданного файла и тест миграции на резервной копии. Начальная схема зафиксирована отдельной ревизией, а не создаётся через динамический `create_all` при каждом старте.

## Внешний адрес и HTTPS

Для локальной проверки достаточно HTTP и привязки к loopback. На удалённой машине используйте SSH-туннель либо reverse proxy. Для публикации за HTTPS:

- Настройте TLS в Nginx/Caddy; ограничьте размер тела 512 МБ или меньше и разрешите передачу больших файлов без короткого таймаута.
- Задайте `PUBLIC_ORIGIN=https://video.example.org`, `COOKIE_SECURE=true` и оставьте host binding `127.0.0.1`.
- Проксируйте только web:8000. S3, PostgreSQL, filer/master не должны быть доступны извне.
- Не доверяйте произвольным forwarded-заголовкам: Uvicorn запускается с `--no-proxy-headers`; Origin для HTTPS сравнивается с PUBLIC_ORIGIN.
- Демо-учётные записи имеют общую тестовую роль/пароль. До реальной эксплуатации замените их учётную политику и уберите демонстрационные материалы.

Пример блока Nginx:

```nginx
location / {
    client_max_body_size 512m;
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_request_buffering off;
    proxy_read_timeout 900s;
    proxy_send_timeout 900s;
}
```

Это фрагмент внутри уже настроенного HTTPS server-блока, не полная TLS-конфигурация.

## Резервные копии

Копия одной БД не содержит видео. Сохраняйте PostgreSQL, объекты, `.env` и `runtime/s3.json` в защищённом хранилище.

Для согласованной копии остановите изменения:

```bash
docker compose stop web worker
mkdir -p backups
docker compose exec -T db pg_dump -U stackbridge -d stackbridge -Fc > backups/database.dump
docker compose stop storage
```

После остановки storage создайте архив его **тома** средствами Docker/хоста. Имя тома определите через `docker volume ls` и `docker volume inspect`; не угадывайте путь `/var/lib/docker/volumes` и не архивируйте весь Docker. Скопируйте локальные секреты отдельно с закрытыми правами. Затем `docker compose start storage worker web`.

Восстановление проверяйте в отдельном Compose-проекте: восстановите том объектов, загрузите дамп `pg_restore`, используйте соответствующие секреты S3 и проверьте smoke. Непроверенная резервная копия не считается рабочей. Автоматическая схема бэкапов и восстановление после потери диска в этом тестовом не реализованы.

## Ограничения ресурсов

По умолчанию загрузка до 512 МБ, длительность до 3 часов, исходное разрешение до 7680×4320. FFmpeg использует два потока и ограничен 600 секундами, lease worker — 900 секундами. Объём временного `/tmp` в контейнере ограничен 1200 МБ. Очень длинный или сложный файл может завершиться ошибкой обработки даже в пределах лимита загрузки; причина отображается владельцу. Исходник хранится в S3 до удаления видео.

Готовые файлы отдаются API порциями по 256 КиБ; поддерживается один диапазон байтов, некорректные/множественные диапазоны получают 416. Сессии действуют семь дней, удаляются при выходе и очищаются при выдаче новых сессий. Ограничение входа — 20 попыток за 15 минут на IP; для тестовых сред параметр AUTH_RATE_LIMIT можно увеличить. Учитывайте общие NAT и reverse proxy при выборе этого значения.
