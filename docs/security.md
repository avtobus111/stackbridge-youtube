# Модель безопасности

## Доступ к видео

Открытое видео доступно гостю только после успешной обработки и пока не скрыто. Приватное видео доступно владельцу, явно указанным зарегистрированным зрителям и сотрудникам модерации. Модератор/администратор имеет доступ к приватному контенту для проверки жалоб; он не может менять список разрешённых зрителей вместо владельца.

Одна политика применяется в ленте, поиске, канале, плейлистах, комментариях, лайках, детальной информации, обложках и MP4. Недоступный объект возвращает 404. Никакой открытый плейлист не расширяет права на входящие в него видео. Скрытие убирает контент из общего доступа; владелец видит причину. Медиа не кэшируются публично. Новый запрос, включая Range/HEAD, заново проверяет сессию и права. Уже переданные пользователю байты отозвать невозможно; уже открытый поток не обрывается в середине.

S3 не опубликован на host и требует отдельных credentials. Браузер не получает эти credentials, ключи исходников или presigned URL. Исходное имя файла не участвует в пути объекта/файловой системы.

## Аккаунты и запросы

Пароли хешируются scrypt с отдельной случайной солью. Сессия — случайный непрозрачный токен; в БД хранится SHA-256 токена, expiry и CSRF. Cookie HttpOnly, SameSite=Lax, Secure при HTTPS-конфигурации. Выход удаляет серверную сессию. В ответах нет хешей паролей/токенов. Неизвестный логин тоже проходит scrypt-проверку, чтобы не давать очевидный быстрый ответ по наличию пользователя.

Изменяющие действия требуют текущей сессии и X-CSRF-Token. Origin и Sec-Fetch-Site проверяются. Исключения: регистрация/вход (с проверкой Origin и throttling), а также счётчик просмотров (проверка Origin и уникальности зрителя; он не меняет права или контент). CORS для посторонних сайтов не включён. Регистрация запрещает лишние поля, включая роль.

Роли меняет только admin; изменения и решения модерации сохраняются в audit. Последнего admin нельзя понизить. Публичной функции создания администратора нет: первичная учётная запись создаётся до запуска web при инициализации.

## Недоверенные данные

SQL-запросы параметризованы SQLAlchemy, поисковые wildcard-символы экранированы. UI экранирует пользовательские строки, вставляя их в HTML; комментарии не исполняют HTML/JS. CSP, nosniff, запрет встраивания во frame и Referrer-Policy добавляются сервером. Swagger имеет локальные файлы и отдельное разрешение inline-инициализации.

Размер тела ограничивается до/во время чтения. Файл проходит ffprobe, а затем преобразуется в контролируемый MP4. FFmpeg получает аргументы массивом без shell, ограничивает протоколы локальными file/pipe, потоки CPU и длительность обработки. Приложение/worker в Docker работают от непривилегированного пользователя; временные файлы находятся в ограниченном tmpfs.

## Остаточные риски и границы

Это тестовое, а не сервис с промышленной защитой. Нет антивируса, отдельной sandbox VM на каждый файл, CAPTCHA, email-проверки, MFA, административного управления устройствами, биллинга/квот диска и автоматической очистки заброшенных аккаунтов. Scrypt/FFmpeg и хранилище расходуют ресурсы, поэтому публичная эксплуатация требует лимитов на reverse proxy и уровне контейнеров, мониторинга, резервных копий и обновления зависимостей.

Throttling использует IP соединения. За reverse proxy это может быть общий адрес: документированное значение рассчитано на локальную проверку. Конфигурация сознательно не доверяет пользовательским X-Forwarded-For. Публичные demo/admin пароли в исходниках отсутствуют; локально сгенерированный общий DEMO_PASSWORD нужен только для оценочного стенда.
