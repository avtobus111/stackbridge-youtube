# YouTube — тестовое StackBridge / Гуфо

Копия основных сценариев YouTube: настоящая загрузка и обработка видео, просмотр, каналы, подписки, лайки, комментарии, плейлисты, приватный доступ и модерация. Backend — Python/FastAPI, данные — PostgreSQL, объекты — закрытое S3-хранилище SeaweedFS. Веб-интерфейс и API работают на одном адресе.

Это самостоятельный учебный проект. Он не связан с Google или YouTube. Исходное ТЗ сохранено в [docs/requirements.txt](docs/requirements.txt) и [original-spec.docx](docs/original-spec.docx).

## Запуск на чистой Ubuntu

Рекомендуемая среда: Ubuntu 24.04 LTS, 4 ГБ RAM или больше, 10 ГБ свободного места. Для первой установки нужен интернет. Распакуйте весь репозиторий и выполните из его каталога:

```bash
sudo bash start.sh
```

Скрипт установит отсутствующий Docker Engine и Compose из официального репозитория Docker, создаст случайные локальные пароли, соберёт приложение, запустит PostgreSQL и хранилище, применит миграции, добавит демо-данные и запустит веб-сервер с обработчиком. При установленном Docker достаточно `bash start.sh`, если у пользователя есть доступ к движку.

Адрес: **http://localhost:8000**. Swagger: **http://localhost:8000/docs**. В /docs все файлы Swagger локальные, внешний CDN не нужен.

По умолчанию наружу опубликован только веб-порт на `127.0.0.1`. На удалённой машине можно открыть его через SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 user@server
```

Для прямой проверки с другого компьютера измените `BIND_ADDRESS=0.0.0.0` и `PUBLIC_ORIGIN=http://SERVER_IP:8000` в `.env`, затем выполните `docker compose up -d`. Публичное использование требует HTTPS и `COOKIE_SECURE=true`; пример настроек — в [operations.md](docs/operations.md).

**Фактические результаты проверок и ограничения среды приведены в [verification.md](docs/verification.md).** Подготовленная конфигурация Docker сама по себе не считается доказательством запуска на чистой Ubuntu.

## Демо и первый сценарий

В ленте сразу доступны 12 коротких роликов, шесть каналов, плейлисты и комментарии. Все материалы локальные; для просмотра не требуется доступ к сторонним видеосервисам. Это демонстрационные фотоэтюды с движением и синтезированным звуком, а не записи событий или полноценные уроки. Источники фотографий и лицензии — в [asset-credits.md](docs/asset-credits.md).

Скрипт запуска показывает сгенерированный пароль для демо-аккаунтов:

| Логин | Назначение |
| --- | --- |
| `viewer` | Зритель с подписками на демо-каналы |
| `creator` | Пустой канал для проверки загрузки |
| `moderator` | Рассмотрение жалоб и скрытие видео |
| `admin` | Модерация и изменение ролей |

Пароль хранится только в локальном `.env` как `DEMO_PASSWORD`. Посмотреть его повторно: `python3 scripts/configure.py --show-login`. Пароли не входят в исходный ZIP. Повторный запуск не перезаписывает существующие пароли и не дублирует демо-данные.

Можно зарегистрировать свой аккаунт. Затем:

1. «Создать» → выбрать файл → указать название, описание, категорию и доступ.
2. Наблюдать настоящий прогресс передачи файла. После передачи открыть «Мои видео» и дождаться статуса «Опубликовано».
3. Открыть видео, запустить плеер, поставить лайк и оставить комментарий.
4. Для приватного видео открыть «Мои видео» → «Доступ» и указать логины зрителей. Удаление логина отзывает доступ для новых запросов, включая диапазоны файла и обложку.
5. Для проверки модерации отправить жалобу другим аккаунтом и рассмотреть её под `moderator` или `admin`.

## Что реализовано

| Область | Поведение |
| --- | --- |
| Лента и поиск | Превью, категории, пагинация, поиск по названию, лента подписок и понравившиеся видео |
| Просмотр | Нативный HTML5-плеер, H.264/AAC MP4, перемотка через HTTP Range, обложка, счётчик уникальных зрителей |
| Загрузка | Прогресс XHR, лимит 512 МБ, фоновая проверка/перекодирование, видимые ошибки и повторная загрузка |
| Каналы | Название/описание, видео, плейлисты, подписка и её отмена |
| Общение | Лайки, комментарии, удаление своих комментариев, жалобы |
| Плейлисты | Создание, добавление/удаление видео, открытые и личные списки |
| Приватность | Только владелец, явно допущенные зрители и сотрудники модерации; единая проверка доступа в API, поиске, плейлистах и медиа |
| Роли | Пользователь, модератор, администратор; журнал модерации; защита последнего администратора |
| Аккаунты | Регистрация, вход, выход, scrypt, HttpOnly-сессии, CSRF, проверка Origin и ограничение попыток входа |
| Эксплуатация | Compose, миграции Alembic, проверка готовности, сохранение БД/объектов, идемпотентное наполнение |

Приватный файл не выдаётся по публичной ссылке S3: браузер обращается к API, который проверяет текущие права на каждый запрос. Модераторы и администраторы могут просматривать приватные видео для проверки нарушений; это явно показано в интерфейсе выдачи доступа.

## Проверки

Полный набор тестов в отдельном Compose-проекте с временной PostgreSQL:

```bash
bash scripts/test.sh
```

Дополнительная проверка уже запущенного приложения использует настоящие PostgreSQL, S3 и worker:

```bash
python3 scripts/smoke.py http://localhost:8000
```

Браузерные сценарии:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
python3 scripts/browser_test.py
```

На Windows с установленным Edge: `python scripts/browser_test.py --channel msedge`.

Для нативной разработки: Python 3.12+, FFmpeg/ffprobe в PATH, отдельные PostgreSQL и S3. Создайте venv, установите `requirements-test.txt`, задайте `DATABASE_URL`, `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` и `DEMO_PASSWORD`. Затем `python -m backend.initialize`, `uvicorn backend.main:app`, отдельным процессом `python -m backend.worker`. Тесты используют `TEST_DATABASE_URL` для **отдельной тестовой БД**; без него применяется SQLite в памяти. Указанная тестовая БД очищается тестами.

Описание архитектуры — [architecture.md](docs/architecture.md), API — [api.md](docs/api.md), эксплуатация и резервные копии — [operations.md](docs/operations.md), модель безопасности — [security.md](docs/security.md), работа с ИИ — [ai/README.md](ai/README.md).

## Границы реализации

Один узел, один вариант MP4, без адаптивного HLS, прямых эфиров, рекомендательной модели, рассылки, восстановления пароля по email и распределённой отказоустойчивости. Перекодирование ограничено по времени и размеру. Сервис хранения и его консоли не публикуются на хосте. Проект предназначен для проверки тестового; готовность к промышленной эксплуатации не заявляется.
